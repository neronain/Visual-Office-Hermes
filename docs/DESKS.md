# รายชื่อโต๊ะ

ไฟล์เดียวที่บอกว่าโต๊ะไหนใช้โมเดลอะไร · อยู่ที่ `~/.hermes/visual-office/desks.yaml`
(เปลี่ยนที่อยู่ได้ด้วย `VISUAL_OFFICE_DESKS=/path/to/desks.yaml`)

---

## โครงไฟล์

```yaml
version: 1

office:
  name: ห้องทำงาน EduLLM          # ชื่อที่ขึ้นหัวจอ

gateway:
  base_url: http://10.0.0.5:8080/v1   # เขียนไว้ให้คนอ่าน ไม่ได้ถูกใช้เรียกจริง

desks:
  - id: coder                     # ชื่อที่โมเดลใช้เรียก — ต้องไม่ซ้ำ
    label: ช่างโค้ด                # ชื่อที่คนอ่าน ขึ้นบนป้ายโต๊ะและใต้ตัวละคร
    model: coder-next             # ชื่อโมเดลที่ลูกจะถูกปักหมุดไว้
    origin: local                 # local | cloud | unknown — คุมสีปลอกคอและแถบข้างโต๊ะ
    provider: litegate            # ป้ายกำกับเฉย ๆ ไม่ได้ใช้เรียก
    note: โมเดลโค้ด 80B MoE        # บรรทัดคำอธิบายในแผงข้าง
    toolsets: [file, terminal, web, todo]
    role: leaf                    # leaf (ค่าตั้งต้น) | orchestrator
```

| ช่อง | บังคับ | ความหมาย |
|---|---|---|
| `id` | ✅ | ชื่อที่ใช้ใน `office_delegate` · เข้าไปอยู่ใน enum ของ schema เครื่องมือด้วย |
| `model` | ✅ | ส่งตรงเข้า `SubagentLaunchRequest.model` |
| `label` | | ค่าตั้งต้นคือ `id` |
| `origin` | | `local` = เขียว (GPU เรา) · `cloud` = เหลือง (จ่ายตามใช้) · อย่างอื่น = เทา |
| `provider` | | ป้ายกำกับสำหรับคนอ่าน |
| `note` | | คำอธิบายสั้น ๆ |
| `toolsets` | | จำกัดเครื่องมือของลูก · **ต้องเป็นสับเซตของ toolset ที่ตัวแม่เปิดอยู่** ไม่งั้น `launch()` จะปฏิเสธ |
| `role` | | `orchestrator` ให้ลูกแตกลูกต่อได้ ภายใต้ `delegation.max_spawn_depth` |

ค่าที่ผิดจะไม่ทำให้ทั้งไฟล์ล่ม — โต๊ะที่มีปัญหาถูกข้าม แล้วเหตุผลจะขึ้นในแผง
"ปัญหาของรายชื่อโต๊ะ" บนหน้าจอ และใน log ของ Hermes

**แก้ไฟล์แล้วต้องเริ่ม session ใหม่** — รายชื่อถูกอ่านตอนโหลดปลั๊กอิน และ schema
ของเครื่องมือ (ที่บอกโมเดลว่ามีโต๊ะอะไรบ้าง) ถูกสร้างตอนนั้นครั้งเดียว

## ตั้งโต๊ะให้ไปถึงหลายผู้ให้บริการ

โต๊ะเก็บได้แค่ชื่อโมเดล — ปลายทางจริงมาจากตัวแม่ · จะให้โต๊ะหนึ่งไป Claude
อีกโต๊ะไป GPU ในตึก ต้องมี gateway คั่นกลาง

### 1. ตั้ง alias ใน LiteGate

alias หนึ่งตัวต่อหนึ่งโต๊ะ ชี้ไป endpoint ที่ต้องการ (เครื่องเราหรือคลาวด์)
LiteGate มีค่าตั้งต้นของผู้ให้บริการคลาวด์มาให้แล้ว — Gemini, MiniMax (Global/จีน),
OpenRouter, OpenAI, Anthropic (ตัวหลังใช้ `x-api-key` ไม่ใช่ Bearer ซึ่งแยกชนิดไว้แล้ว)

### 2. ชี้ Hermes ไป LiteGate

```yaml
# ~/.hermes/config.yaml
model:
  default: claude-sonnet-4.8        # alias ของ LiteGate
  provider: custom
  base_url: http://10.0.0.5:8080/v1
```

คีย์ใส่ผ่าน `hermes model` หรือ `.env` — อย่าเขียนลง `config.yaml`

### 3. ให้ชื่อโต๊ะตรงกับ alias

```yaml
desks:
  - { id: coder,   label: ช่างโค้ด,   model: coder-next,        origin: local }
  - { id: review,  label: คนตรวจงาน,  model: claude-sonnet-4.8, origin: local }
  - { id: vision,  label: คนดูรูป,    model: gemini-2.5-flash,  origin: cloud }
```

### ตรวจว่าคีย์เรียก alias ไหนได้จริง

```bash
curl -s -H "Authorization: Bearer $LITEGATE_KEY" http://10.0.0.5:8080/v1/models
```

ถ้า alias ของโต๊ะไม่อยู่ในผลลัพธ์ ลูกที่นั่งโต๊ะนั้นจะล้มตอนเรียก ไม่ใช่ตอนสร้าง

## กับดักที่เจอบ่อย

**ตั้งชื่อโมเดลมั่ว แล้วดูเหมือนใช้ได้** — llama.cpp ไม่ตรวจช่อง `model`
ขออะไรไปก็ตอบด้วยตัวที่โหลดไว้ · ถ้าตัวแม่ชี้ตรงไป llama.cpp โต๊ะทุกตัวจะ "ทำงานได้"
ทั้งที่วิ่งบนโมเดลเดียวกันหมด · หน้าจอจะแสดงชื่อที่คุณตั้ง ซึ่ง **ไม่ใช่** สิ่งที่ backend ทำจริง
— มี gateway คั่นกลางเท่านั้นที่ทำให้ชื่อโมเดลกลายเป็นการเลือกเครื่องจริง

**`toolsets` กว้างกว่าตัวแม่** — `launch()` ปฏิเสธพร้อมข้อความว่า toolset ไหนเกิน
ลดให้เป็นสับเซตของที่ตัวแม่เปิดอยู่ (ดู `platform_toolsets` ใน `config.yaml`)

**โต๊ะเยอะเกินกว่าจะรันพร้อมกัน** — จำนวนลูกที่รันพร้อมกันคุมด้วย
`delegation.max_concurrent_children` ของ Hermes ไม่ใช่จำนวนโต๊ะ · โต๊ะที่เกินจะรอคิว

**หนึ่งโต๊ะนั่งได้หลายคน** — ห้องวาดหลายตัวละครที่โต๊ะเดียวกันได้ ถ้าส่งงานไปโต๊ะเดิม
หลายงานพร้อมกัน · ยอดโทเคนของโต๊ะรวมทุกคนที่เคยนั่ง
