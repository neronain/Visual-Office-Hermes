# รายชื่อโต๊ะ

ไฟล์เดียวที่บอกว่าโต๊ะไหนใช้โมเดลอะไร · อยู่ที่ `~/.hermes/visual-office/desks.yaml`
(เปลี่ยนที่อยู่ได้ด้วย `VISUAL_OFFICE_DESKS=/path/to/desks.yaml`)

---

## แก้จากหน้าเว็บ (ไม่ต้องแตะไฟล์)

กดปุ่ม **จัดการ** ข้างหัวข้อ "โต๊ะและโมเดล" ในแผงขวา — เพิ่ม แก้ ลบโต๊ะได้จากตรงนั้น

**มีผลกับ Hermes ทันที ไม่ต้อง restart** · ปลั๊กอินดูเวลาแก้ไขของไฟล์ทุกครั้งก่อนเรียกโมเดล
ถ้าไฟล์เปลี่ยน มันจะอ่านใหม่และลงทะเบียนเครื่องมือ `office_delegate` ใหม่พร้อม
รายชื่อโต๊ะชุดใหม่ · โต๊ะที่เพิ่งเพิ่มจึงสั่งได้ตั้งแต่ข้อความถัดไป

| | |
|---|---|
| อ่านรายชื่อ | เปิดให้ทุกคนที่เข้าถึงพอร์ตได้ |
| บันทึก | ต้องมี token · เครื่องเดียวกับเซิร์ฟเวอร์ได้ token อัตโนมัติ · เครื่องอื่นถูกถามครั้งเดียวแล้วจำไว้ |
| สำรองไฟล์ | เขียนทับ `desks.yaml.bak` ทุกครั้งที่บันทึก |
| คอมเมนต์ในไฟล์ | **หายไป** เมื่อบันทึกจากหน้าเว็บ เพราะไฟล์ถูกเขียนใหม่ทั้งไฟล์ |

⚠️ **แก้ไฟล์ด้วยมือระหว่างที่ Hermes ยังไม่ได้รัน** — หน้าเว็บจะไม่รู้ว่าไฟล์เปลี่ยน
(มันไม่ได้อ่าน YAML เอง) จึงขึ้นคำเตือนให้เริ่ม session ของ Hermes สักครั้งก่อนกดบันทึก
ไม่งั้นจะทับของที่แก้ไว้ · แก้จากหน้าเว็บอย่างเดียวไม่มีปัญหานี้

⚠️ **เซิร์ฟเวอร์ห้องต้องอยู่เครื่องเดียวกับ Hermes** ถึงจะแก้จากหน้าเว็บได้ —
ถ้าคนละเครื่อง ปุ่มบันทึกจะถูกปิดพร้อมบอกว่าไฟล์จริงอยู่ที่ไหน

---

## โครงไฟล์

```yaml
version: 1

office:
  name: ห้องทำงาน EduLLM          # ชื่อที่ขึ้นหัวจอ

gateway:
  base_url: http://10.0.0.5:8080/v1   # เขียนไว้ให้คนอ่าน ไม่ได้ถูกใช้เรียกจริง

desks:
  - id: coder                     # ชื่อที่โมเดลใช้เรียก — ต้องไม่ซ้ำ
    label: ช่างโค้ด                # ชื่อที่คนอ่าน ขึ้นบนป้ายโต๊ะและใต้ตัวละคร
    model: coder-next             # ชื่อโมเดลที่ลูกจะถูกปักหมุดไว้
    origin: local                 # local | cloud | unknown — คุมสีปลอกคอและแถบข้างโต๊ะ
    provider: litegate            # ป้ายกำกับเฉย ๆ ไม่ได้ใช้เรียก
    note: โมเดลโค้ด 80B MoE        # บรรทัดคำอธิบายในแผงข้าง
    toolsets: [file, terminal, web, todo]
    role: leaf                    # leaf (ค่าตั้งต้น) | orchestrator
```

| ช่อง | บังคับ | ความหมาย |
|---|---|---|
| `id` | ✅ | ชื่อที่ใช้ใน `office_delegate` · เข้าไปอยู่ใน enum ของ schema เครื่องมือด้วย |
| `model` | ✅ | ส่งตรงเข้า `SubagentLaunchRequest.model` |
| `label` | | ค่าตั้งต้นคือ `id` |
| `origin` | | `local` = เขียว (GPU เรา) · `cloud` = เหลือง (จ่ายตามใช้) · อย่างอื่น = เทา |
| `provider` | | ป้ายกำกับสำหรับคนอ่าน |
| `note` | | คำอธิบายสั้น ๆ |
| `toolsets` | | จำกัดเครื่องมือของลูก · **ต้องเป็นสับเซตของ toolset ที่ตัวแม่เปิดอยู่** ไม่งั้น `launch()` จะปฏิเสธ |
| `role` | | `orchestrator` ให้ลูกแตกลูกต่อได้ ภายใต้ `delegation.max_spawn_depth` |

ค่าที่ผิดจะไม่ทำให้ทั้งไฟล์ล่ม — โต๊ะที่มีปัญหาถูกข้าม แล้วเหตุผลจะขึ้นในแผง
"ปัญหาของรายชื่อโต๊ะ" บนหน้าจอ และใน log ของ Hermes

**แก้แล้วมีผลตั้งแต่ข้อความถัดไป** — ปลั๊กอินดูเวลาแก้ไขของไฟล์ก่อนเรียกโมเดลทุกครั้ง
ถ้าเปลี่ยนก็อ่านใหม่และลงทะเบียนเครื่องมือ `office_delegate` ใหม่พร้อม enum ของโต๊ะชุดใหม่
ไม่ต้อง restart อะไรทั้งนั้น

## ตั้งโต๊ะให้ไปถึงหลายผู้ให้บริการ

โต๊ะเก็บได้แค่ชื่อโมเดล — ปลายทางจริงมาจากตัวแม่ · จะให้โต๊ะหนึ่งไป Claude
อีกโต๊ะไป GPU ในตึก ต้องมี gateway คั่นกลาง

### 1. ตั้ง alias ใน LiteGate

alias หนึ่งตัวต่อหนึ่งโต๊ะ ชี้ไป endpoint ที่ต้องการ (เครื่องเราหรือคลาวด์)
LiteGate มีค่าตั้งต้นของผู้ให้บริการคลาวด์มาให้แล้ว — Gemini, MiniMax (Global/จีน),
OpenRouter, OpenAI, Anthropic (ตัวหลังใช้ `x-api-key` ไม่ใช่ Bearer ซึ่งแยกชนิดไว้แล้ว)

### 2. ชี้ Hermes ไป LiteGate

```yaml
# ~/.hermes/config.yaml
model:
  default: claude-sonnet-4.8        # alias ของ LiteGate
  provider: custom
  base_url: http://10.0.0.5:8080/v1
```

คีย์ใส่ผ่าน `hermes model` หรือ `.env` — อย่าเขียนลง `config.yaml`

### 3. ให้ชื่อโต๊ะตรงกับ alias

```yaml
desks:
  - { id: coder,   label: ช่างโค้ด,   model: coder-next,        origin: local }
  - { id: review,  label: คนตรวจงาน,  model: claude-sonnet-4.8, origin: local }
  - { id: vision,  label: คนดูรูป,    model: gemini-2.5-flash,  origin: cloud }
```

### ตรวจว่าคีย์เรียก alias ไหนได้จริง

```bash
curl -s -H "Authorization: Bearer $LITEGATE_KEY" http://10.0.0.5:8080/v1/models
```

ถ้า alias ของโต๊ะไม่อยู่ในผลลัพธ์ ลูกที่นั่งโต๊ะนั้นจะล้มตอนเรียก ไม่ใช่ตอนสร้าง

## กับดักที่เจอบ่อย

**ตั้งชื่อโมเดลมั่ว แล้วดูเหมือนใช้ได้** — llama.cpp ไม่ตรวจช่อง `model`
ขออะไรไปก็ตอบด้วยตัวที่โหลดไว้ · ถ้าตัวแม่ชี้ตรงไป llama.cpp โต๊ะทุกตัวจะ "ทำงานได้"
ทั้งที่วิ่งบนโมเดลเดียวกันหมด · หน้าจอจะแสดงชื่อที่คุณตั้ง ซึ่ง **ไม่ใช่** สิ่งที่ backend ทำจริง
— มี gateway คั่นกลางเท่านั้นที่ทำให้ชื่อโมเดลกลายเป็นการเลือกเครื่องจริง

**`toolsets` กว้างกว่าตัวแม่** — `launch()` ปฏิเสธพร้อมข้อความว่า toolset ไหนเกิน
ลดให้เป็นสับเซตของที่ตัวแม่เปิดอยู่ (ดู `platform_toolsets` ใน `config.yaml`)

**โต๊ะเยอะเกินกว่าจะรันพร้อมกัน** — จำนวนลูกที่รันพร้อมกันคุมด้วย
`delegation.max_concurrent_children` ของ Hermes ไม่ใช่จำนวนโต๊ะ · โต๊ะที่เกินจะรอคิว

**หนึ่งโต๊ะนั่งได้หลายคน** — ห้องวาดหลายตัวละครที่โต๊ะเดียวกันได้ ถ้าส่งงานไปโต๊ะเดิม
หลายงานพร้อมกัน · ยอดโทเคนของโต๊ะรวมทุกคนที่เคยนั่ง

## "อยากให้โต๊ะชี้ตรงไปเครื่องหนึ่งเลย ได้ไหม"

**ไม่ได้** — และไม่ใช่ข้อจำกัดของโปรเจกต์นี้ แต่เป็นของ Hermes เอง

`SubagentLaunchRequest` มีแค่ `model` ไม่มี `base_url` / `api_key` / `provider`
ลูกได้ปลายทางจากตัวแม่เสมอ ดังนั้นทุกโต๊ะวิ่งผ่านประตูเดียวกันเสมอ —
สิ่งเดียวที่ต่างกันได้คือชื่อโมเดล

วิธีที่ให้ผลเหมือนกันคือ **ทำให้เครื่องนั้นเป็น alias ใน gateway** แล้วโต๊ะชี้ที่ alias
คำขอก็วิ่งตรงไปเครื่องนั้น ต่างกันแค่ผ่าน gateway หนึ่ง hop ซึ่งเป็นที่ที่โควตา
การนับ และ failover อยู่พอดี

```yaml
# /opt/litegate/config/models/vision-next.yaml
metadata:
  alias: vision-next
spec:
  endpoints:
    - name: vision-8000
      base_url: http://100.107.151.68:8000   # ← เครื่องที่อยากชี้ตรง
      server_type: llama.cpp
```

```yaml
# desks.yaml
- id: vision
  label: คนดูรูป
  model: vision-next
  origin: local
```

LiteGate อ่านโฟลเดอร์ `config/models/` ใหม่ทุก 30 วินาที และการโหลดเป็น atomic
(ไฟล์ไหนไม่ผ่านการตรวจ จะคง snapshot เดิมไว้ทั้งชุด) — วาง alias ใหม่ได้โดยไม่ต้อง
restart และไม่มีช่วงบริการขาด

⚠️ **อย่าลืมให้สิทธิ์คีย์ด้วย** — alias ใหม่ที่ไม่ได้อยู่ในรายการโมเดลของ API key
จะไม่โผล่ใน `/v1/models` และลูกที่นั่งโต๊ะนั้นจะได้ 401 เพิ่มสิทธิ์ในคอนโซล LiteGate
ที่หน้า API keys

## โต๊ะมีสองแบบ: ผ่าน gateway กับยิงตรง

ช่อง **ต่อผ่าน** ในหน้าจัดการโต๊ะเลือกได้ทีละโต๊ะ ไม่ใช่ทั้งห้องเหมือนกันหมด

| | ผ่าน gateway | ยิงตรงไปที่ endpoint เอง |
|---|---|---|
| เป็นอะไร | subagent เต็มรูปของ Hermes | ถาม-ตอบล้วน ๆ ผ่าน HTTP |
| tools | ใช้ได้ | **ไม่มี** |
| session / agent loop | มี | ไม่มี |
| gateway ล่มแล้ว | ตายตาม | **ยังทำงานต่อได้** |
| ตั้งค่า | เว้น `base_url` ว่างไว้ | ใส่ `base_url` (กับ `api_key_env` ถ้า endpoint ต้องใช้คีย์) |

### ทำไมต้องมีสองแบบ

`SubagentLaunchRequest` ของ Hermes รับแค่ชื่อโมเดล ไม่มีช่องให้ใส่ base_url — ลูกจึง
สืบ endpoint จากพ่อเสมอ นั่นแปลว่า **โต๊ะที่เป็น subagent จริงทุกตัวใช้ประตูเดียวกัน**
และ alias ของ gateway คือสิ่งเดียวที่พาโต๊ะแต่ละตัวไปลงคนละเครื่องได้

ข้อดีคือได้ tools กับ session ครบ ข้อเสียคือ gateway กลายเป็นจุดตายจุดเดียว

โต๊ะที่ใส่ `base_url` เองจะข้าม Hermes ไปเลย คุยกับ endpoint นั้นตรง ๆ แบบ
OpenAI-compatible แลก tools ทิ้งไปเพื่อให้ยังตอบได้ตอน gateway ล่ม

### ตัวอย่าง

```yaml
desks:
  # ผ่าน gateway — ได้ tools ครบ
  - id: "coder"
    label: "ช่างโค้ด"
    model: "claude-opus-4.8"
    toolsets: ["file", "terminal", "web"]

  # ยิงตรง — ไม่ตายตาม gateway
  - id: "thinker"
    label: "หัวคิด"
    model: "huihui-gpt-oss-120b-abliterated-mxfp4-moe-gguf"
    base_url: "http://100.78.221.35:8011/v1"

  # ยิงตรง + ต้องใช้คีย์
  - id: "cloud"
    label: "ตัวนอก"
    model: "gpt-4o-mini"
    base_url: "https://api.example.com/v1"
    api_key_env: "EXAMPLE_API_KEY"
```

`api_key_env` เก็บ **ชื่อตัวแปรสภาพแวดล้อม** ไม่ใช่ตัวคีย์ — ไฟล์ roster ถูกอ่านผ่าน API
ได้ทั้งไฟล์ คีย์จึงไม่ควรอยู่ในนั้น · ปลั๊กอินหาค่าจาก environment ก่อน แล้วค่อยจาก
`~/.hermes/.env`

`toolsets` ของโต๊ะที่ยิงตรงถูกเมิน และตัวอ่าน roster จะเตือนไว้ให้ ไม่ปล่อยให้เข้าใจผิดว่าตั้งแล้วได้ผล

### สั่งงานจากห้อง

โต๊ะที่ยิงตรงถูกเรียก **ทันที** จากช่องสั่งงาน ไม่ผ่านโมเดลหลัก — เดิมคำสั่งถูกฉีดเป็น
ข้อความเข้าแชทแล้วรอโมเดลหลักอ่านและตัดสินใจเรียก `office_delegate` เอง กว่าโต๊ะจะเริ่ม
ทำงานก็ผ่านไปเป็นนาที และคำสั่งหลายอันต่อคิวกันอยู่ในบทสนทนาเดียว

โต๊ะที่ผ่าน gateway ยังใช้ทางเดิม เพราะมันต้องการ session กับ tools ของ Hermes จริง ๆ

คนที่นั่งโต๊ะยิงตรงเป็นคนเดิมตลอด ไม่ใช่คนใหม่ทุกครั้งที่สั่งงาน — สั่งซ้ำที่โต๊ะเดิม
ตัวละครเดิมจะกลับมาทำงาน ไม่ใช่มีคนใหม่เดินเข้ามาแล้วเดินออกไปทุกรอบ
