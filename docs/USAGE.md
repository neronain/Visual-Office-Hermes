# ใช้งานยังไง

เขียนสำหรับคนที่เพิ่งเริ่ม · ถ้าอ่านแล้วยังติด ปัญหาส่วนใหญ่อยู่ในหัวข้อสุดท้าย

---

## สิ่งแรกที่ต้องเข้าใจ: คุณไม่ได้เรียกเครื่องมือเอง

Hermes เป็นเอเจนต์ — **คุณพูดภาษาคน แล้วมันเลือกเครื่องมือเอง**
ไม่มีคำสั่งแบบ `/delegate` ให้พิมพ์ และไม่ต้องเขียน JSON

```
ส่งงานตรวจโค้ดไฟล์ app.py ไปที่โต๊ะ reviewer
```

แค่นี้ · โมเดลจะเห็นคำว่า "โต๊ะ reviewer" แล้วเรียก `office_delegate` ให้เอง

---

## มีเครื่องมือแตกงานอยู่สองตัว

| | `delegate_task` | `office_delegate` |
|---|---|---|
| มากับ | Hermes เอง | ปลั๊กอินนี้ |
| โมเดลของลูกน้อง | **ตัวเดียวทั้งหมด** (`delegation.model` ใน config) | **แยกตามโต๊ะ** |
| ในห้องพิกเซล | ตัวละครไม่มีโต๊ะ อยู่ห้องพัก | นั่งโต๊ะที่ระบุ จอติด นับโทเคนแยก |
| ใช้เมื่อ | ไม่สนว่าลูกใช้โมเดลไหน | อยากเลือกสมองให้แต่ละงาน |

เปิดใช้พร้อมกันได้ ไม่ตีกัน

**คำที่ทำให้โมเดลเลือกตัวไหน** — พูดคำว่า *"โต๊ะ"* หรือชื่อโต๊ะตรง ๆ
(`coder` / `reviewer` / `runner`) มันจะใช้ `office_delegate` · ถ้าพูดลอย ๆ ว่า
"ช่วยแตกงานหน่อย" มันจะใช้ `delegate_task` ซึ่งลูกทุกตัวได้โมเดลเดียวกัน

บังคับชัด ๆ ได้ด้วยการเรียกชื่อเครื่องมือ:

```
ใช้เครื่องมือ office_delegate ส่งงานนี้ไปโต๊ะ coder
```

---

## ตัวอย่างที่ใช้ได้จริง

```
มีโต๊ะอะไรให้ใช้บ้าง
```
> โมเดลเรียก `office_delegate` แบบ `action: list` แล้วตอบรายชื่อโต๊ะ + ชื่อโมเดล + ลูกน้องที่ยังทำงานอยู่

```
ส่งงานอ่านไฟล์ /etc/os-release แล้วสรุปเป็นสองบรรทัด ไปที่โต๊ะ runner
```
> ลูกน้องหนึ่งตัวเกิดที่โต๊ะ runner ปักหมุดโมเดลของโต๊ะนั้น ทำเสร็จแล้วส่งสรุปกลับมา

```
แตกงานเป็นสองส่วน — ให้โต๊ะ coder เขียนสคริปต์สำรองข้อมูล
แล้วให้โต๊ะ reviewer ตรวจว่าสคริปต์นั้นปลอดภัยไหม
```
> สองตัว สองโต๊ะ สองโมเดล

```
งานที่ส่งไปโต๊ะ coder เมื่อกี้ถึงไหนแล้ว
```
> `action: status`

## เพิ่ม / ลบ / แก้โต๊ะ

กดปุ่ม **จัดการ** ข้างหัวข้อ "โต๊ะและโมเดล" ในแผงขวาของหน้าห้อง

| ช่อง | ใส่อะไร |
|---|---|
| **id** | ชื่อที่พิมพ์สั่งงาน — ตัวเล็ก ตัวเลข `_` `-` เท่านั้น เช่น `coder` |
| **ชื่อที่คนอ่าน** | ขึ้นบนป้ายโต๊ะ เช่น `ช่างโค้ด` |
| **มาจาก** | เครื่องเรา (เขียว) / คลาวด์ (เหลือง) — คุมสีในห้องเท่านั้น ไม่ได้เปลี่ยนปลายทาง |
| **model** | **ชื่อที่ gateway เรียกได้จริง** · เลือกจากรายการที่ gateway ตอบมา และใต้ช่องจะบอกความสามารถจริงของโมเดลนั้น (context · รูป · tools · คิดเป็นขั้นตอน) |
| **toolsets** | เครื่องมือที่ลูกน้องโต๊ะนี้ใช้ได้ คั่นด้วย `,` · **ต้องไม่กว้างกว่าที่ตัวแม่เปิดอยู่** |
| **หมายเหตุ** | คำอธิบายสั้น ๆ ขึ้นในแผงขวา |

ช่อง **โมเดลหลัก** ด้านบนคือตัวที่เอเจนต์ตัวแม่ใช้เอง · เปลี่ยนแล้วปลั๊กอินจะเขียนลง
`~/.hermes/config.yaml` ให้ (สำรองไฟล์เดิมไว้ทุกครั้ง) และ **ปฏิเสธโมเดลที่ gateway
ไม่มีให้คีย์นี้เรียก** เพราะถ้าปล่อยผ่าน จะไปพังตอนส่งข้อความถัดไปโดยไม่มีอะไรอธิบาย

> **ค่าตั้งของแต่ละโมเดลอยู่ที่ไหน** — อยู่ที่ gateway หนึ่งไฟล์ต่อหนึ่งโมเดล
> (`config/models/<alias>.yaml` ของ LiteGate) แต่ละไฟล์มี endpoint ของตัวเอง
> ความสามารถที่วัดมาของตัวเอง และเพดาน context ของตัวเอง · ช่อง Gateway base URL
> ในหน้านี้ไม่ใช่ "ทุกโต๊ะชี้ที่เดียวกัน" — มันคือ *ประตู* หลังประตูแต่ละ alias ไปคนละเครื่อง
> ซึ่งเป็นเหตุผลที่หน้านี้ดึงความสามารถจริงของแต่ละตัวมาแสดงใต้ช่อง model

กดบันทึกแล้ว **ใช้ได้ตั้งแต่ข้อความถัดไป ไม่ต้อง restart** — ปลั๊กอินดูเวลาแก้ไขไฟล์
ก่อนเรียกโมเดลทุกครั้ง เจอว่าเปลี่ยนก็อ่านใหม่และลงทะเบียนเครื่องมือใหม่ให้เอง

สิ่งที่ควรรู้:

- **บันทึกได้ต้องมี token** · เปิดหน้าห้องจากเครื่องเดียวกับเซิร์ฟเวอร์จะได้ token เอง ·
  เครื่องอื่นจะถูกถามครั้งเดียวแล้วจำไว้ (token อยู่ใน `~/.hermes/visual-office/server.json`)
- **คอมเมนต์ในไฟล์จะหายเมื่อบันทึกจากหน้าเว็บ** เพราะไฟล์ถูกเขียนใหม่ทั้งไฟล์ ·
  ไฟล์เดิมถูกสำรองเป็น `desks.yaml.bak` ทุกครั้ง
- **แก้ไฟล์ด้วยมือตอน Hermes ไม่ได้รัน** แล้วมากดบันทึกในหน้าเว็บ จะขึ้นคำเตือนก่อน —
  ให้เริ่ม session ของ Hermes สักครั้ง แล้วค่อยแก้
- **เซิร์ฟเวอร์ห้องต้องอยู่เครื่องเดียวกับ Hermes** ถึงจะแก้ได้ ไม่งั้นปุ่มบันทึกถูกปิด
  พร้อมบอกว่าไฟล์จริงอยู่ที่ไหน

## เห็นคำตอบในห้อง

แผงขวามีช่อง **ตอบกลับมาว่าอะไร** — คำตอบของเอเจนต์ คำถามที่รออนุมัติ และผลการอนุมัติ
จะขึ้นที่นี่ ไม่ต้องเปิดแชทค้างไว้

| สี | คืออะไร |
|---|---|
| เทา | คำตอบปกติ |
| แดง | **รออนุมัติ** — พร้อมคำสั่งที่มันขออนุญาตรัน |
| เหลือง | ผลการอนุมัติ |

**เก็บในหน่วยความจำเท่านั้น ไม่เขียนลงดิสก์** — `events.jsonl` เก็บสถานะของห้อง
ไม่ใช่บทสนทนา · restart เซิร์ฟเวอร์แล้วรายการนี้จะหายไป ซึ่งตั้งใจให้เป็นแบบนั้น
· คำสั่งที่ขออนุมัติถูก Hermes กรองข้อมูลอ่อนไหวออกให้ก่อนแล้ว

## สั่งงานจากหน้าเว็บ

แผงขวามีช่อง **สั่งงาน** — เลือกปลายทาง (— ตัวหลัก — หรือชื่อโต๊ะ) พิมพ์งาน แล้วกด **ส่ง**
(หรือ `Ctrl+Enter`)

**คำตอบจะกลับไปที่แชทที่คุยอยู่ ไม่ใช่บนหน้าเว็บ** — ถ้าคุยผ่าน Telegram คำตอบก็ไปที่
Telegram · หน้าเว็บแสดงว่ากำลังทำงานอยู่ (ตัวละครเดินไปนั่งโต๊ะ จอติด) แต่ไม่แสดงข้อความ

### ทำไมถึงเป็นแบบนี้

สิ่งที่อยู่นอก turn สร้าง subagent เองไม่ได้ เพราะการสร้างต้องมี "ตัวแม่" ผูกอยู่กับ
context ที่เรียก · ทางที่ทำได้จากข้างนอกคือ **ส่งข้อความเข้า session ที่ยังมีชีวิตอยู่**
แล้วให้ Hermes ทำงานตามปกติ · หน้าเว็บจึงเข้าคิวงานไว้ ปลั๊กอินมาดึงไปทุก 2 วินาที
แล้วส่งเข้า session ล่าสุด

ผลที่ตามมาที่ต้องรู้:

- **ส่งได้เลยแม้เพิ่ง restart** — ปลั๊กอินหาปลายทางจากสามทางตามลำดับ: session ที่เห็นในรอบนี้ →
  ที่จำไว้จากรอบก่อน (`sessions.json`) → ช่องที่ Hermes รู้จักใน `channel_directory.json`
  ซึ่งประกอบ session key ด้วยฟังก์ชันของ Hermes เอง · จะขึ้นข้อความให้ไปคุยก่อนก็ต่อเมื่อ
  ยังไม่เคยมีใครคุยกับ Hermes เลยสักครั้ง
- **ถ้า Hermes กำลังทำงานอยู่ ข้อความจะไปขัดจังหวะ** แล้วต่อคิวเป็นงานถัดไป
- เลือกโต๊ะ = ระบบจะเติมข้อความให้เองว่า `ใช้เครื่องมือ office_delegate ส่งงานนี้ไปที่โต๊ะ …`

### สิทธิ์ที่ต้องเปิด

Hermes กันการที่ปลั๊กอินจะเริ่ม turn เองไว้เป็นค่าตั้งต้น · ต้องเปิดใน `~/.hermes/config.yaml`:

```yaml
plugins:
  entries:
    visual_office:
      allow_gateway_injection: true
```

ปิดกลับได้ด้วยการลบบรรทัดนั้น (หรือเปลี่ยนเป็น `false`) แล้ว restart gateway ·
ปิดแล้วส่วนอื่นของห้องยังทำงานปกติ เสียแค่ช่องสั่งงาน

## สั่งจากไหนได้บ้าง

### CLI

```bash
hermes                      # โหมดคุยต่อเนื่อง
hermes -z "ข้อความ" --yolo   # สั่งครั้งเดียวจบ (--yolo = อนุมัติเครื่องมือให้อัตโนมัติ)
```

### Telegram / Discord / แพลตฟอร์มอื่น

พิมพ์ในแชทเหมือนคุยกับคน · ตัวละครในห้องจะชื่อ `telegram` แทน `cli`

> ⚠️ **ปลั๊กอินโหลดตอน process เริ่มเท่านั้น**
>
> gateway (ตัวที่คุม Telegram) เป็นคนละ process กับ CLI · ติดตั้งหรืออัปเดตปลั๊กอิน
> แล้ว **ต้อง restart gateway** ไม่งั้นฝั่ง Telegram จะไม่เห็น `office_delegate` เลย
> ทั้งที่ฝั่ง CLI ใช้ได้ปกติ
>
> ```bash
> hermes gateway restart
> ```
>
> เช็คว่าโหลดแล้ว — ปลั๊กอินเขียน log ลง **`agent.log`** ไม่ใช่ `gateway.log`
> (หา `visual_office` ใน `gateway.log` จะได้ 0 เสมอแม้ทุกอย่างปกติ):
> ```bash
> grep "visual_office ready" ~/.hermes/logs/agent.log | tail -1
> ```
> เทียบเวลาที่ได้กับเวลาที่ gateway เริ่ม — ถ้าใหม่กว่า แปลว่า gateway ตัวปัจจุบันโหลดแล้ว
>
> หรือเช็คจากปลายทางเลย: สั่งงานผ่าน Telegram หนึ่งครั้ง แล้วดูว่ามีตัวละครชื่อ
> `telegram` โผล่ในห้องไหม

## ดูผลที่ห้องพิกเซล

เปิดหน้าห้องค้างไว้ระหว่างสั่งงาน แล้วดูว่า:

| เห็นอะไร | แปลว่า |
|---|---|
| ตัวละครเดินเข้าประตู | session เริ่มแล้ว |
| เดินไปนั่งโต๊ะ จอติด | กำลังทำงานบนโมเดลของโต๊ะนั้น |
| ท่าพิมพ์ / ท่าถืออ่าน | กำลังเขียนไฟล์ / กำลังค้นหาอ่าน |
| ฟองสีเหลืองสามจุด | กำลังรอโมเดลตอบ |
| ฟองอุทานสีแดง | **รออนุมัติจากคุณ** ไปตอบในแชท |
| ลุกเดินเตร่ นั่งโซฟา | ตอบเสร็จแล้ว กำลังรอข้อความถัดไป |
| เดินออกประตูแล้วจาง | ลูกน้องทำงานเสร็จ หรือ session ถูกปิด/รีเซ็ตจริง ๆ |

**session หลักจะไม่หายไปเมื่อตอบเสร็จ** — มันแค่ลุกจากโต๊ะไปนั่งรอ พอส่งข้อความใหม่
ก็เดินกลับมานั่งทำงานต่อ · จะหายไปก็ต่อเมื่อปิด session จริง (`/new`, ออกจากโปรแกรม,
session หมดอายุ) หรือเงียบไปเกินครึ่งชั่วโมง

ตัวเลขมุมขวาบนเป็นยอดสะสม ไม่ได้ลดลงตอนคนเดินออก

## เมื่อไม่เป็นอย่างที่คิด

**"โมเดลไม่ยอมใช้ office_delegate"**
พูดคำว่า "โต๊ะ" หรือชื่อโต๊ะให้ชัด หรือสั่งตรง ๆ ว่า `ใช้เครื่องมือ office_delegate`

**"บอก Unknown desk"**
ชื่อโต๊ะไม่ตรงกับ `desks.yaml` · ถาม `มีโต๊ะอะไรบ้าง` เพื่อดูชื่อจริง

**"แก้ desks.yaml แล้วไม่เปลี่ยน"**
ปกติไม่ต้องทำอะไร — ปลั๊กอินดูเวลาแก้ไขไฟล์ก่อนเรียกโมเดลทุกครั้ง เจอว่าเปลี่ยนก็อ่านใหม่เอง
ถ้ายังไม่เปลี่ยน ให้ดูว่าแก้ไฟล์ถูกตัวไหม (`~/.hermes/visual-office/desks.yaml`
หรือที่ `VISUAL_OFFICE_DESKS` ชี้ไป) และไฟล์นั้นผ่าน YAML จริงไหม — โต๊ะที่ผิดรูปแบบ
จะถูกข้ามพร้อมบอกเหตุผลในแผง "ปัญหาของรายชื่อโต๊ะ" บนหน้าจอ

**"ได้ 429 All backends at capacity"**
ยิงพร้อมกันเกินที่ backend รับไหว · `max_concurrency` ของ endpoint ใน LiteGate
มักตั้งไว้ที่ 1 ซึ่งแปลว่าตัวแม่ + ลูกสองตัวก็เต็มแล้ว · **เริ่มจากทีละโต๊ะก่อน**
จะขนานต้องขยาย `max_concurrency` ที่ gateway

**"ได้ 401 Invalid API key"**
คีย์ของ custom endpoint ต้องอยู่ใน `~/.hermes/.env` ชื่อที่ Hermes สร้างเอง
(`HERMES_CUSTOM_<HOST>_<PORT>_API_KEY`) และ `config.yaml` อ้างด้วย
`model.api_key: ${...}` · ใช้ `scripts/point_at_gateway.py` จะตั้งให้ถูกทั้งชุด

**"ต้องใส่ token ตอนกดส่ง"**
ปกติสำหรับเบราว์เซอร์ที่ไม่ได้อยู่เครื่องเดียวกับเซิร์ฟเวอร์ห้อง — ใส่ครั้งเดียวแล้วจำไว้
หาได้จาก `~/.hermes/visual-office/server.json` · token ไม่เปลี่ยนเมื่อ restart แล้ว

**"ห้องว่างทั้งที่กำลังสั่งงานอยู่"**
เซิร์ฟเวอร์ห้องไม่ได้รัน หรือปลั๊กอินหาไม่เจอ · เช็ค:
```bash
curl -s http://127.0.0.1:8130/healthz
```
